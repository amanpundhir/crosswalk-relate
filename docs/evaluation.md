# Evaluation

The short version is in the [README](../README.md#the-result). This page has the full tables, how they were measured, and what they do not show.

Honesty rules: the company data is fictional; the agent comparison is one model (Claude Sonnet), one question set and published transcripts, with no claims beyond that; where a target was missed, the real number is shown. Everything here is in [`eval/scorecard.md`](../eval/scorecard.md), regenerated by `crosswalk scorecard`. Agent figures are read from the recorded runs (running agents needs a model account, so you read the transcripts instead of re-running them). All other figures are computed from the committed store with no AI call.

## Agent comparison: same model, same 20 questions, three setups

Protocol: [`eval/agent_compare/README.md`](../eval/agent_compare/README.md). Scoring is mechanical (`eval/score_agents.py`): a question is correct only if every key of the structured answer matches the independent pure-Python oracle ([`eval/oracle.py`](../eval/oracle.py)). A "wrong claim shown" is a cited path that fails the claim checker at the store's date (expired, only proposed, rejected, not adopted, fabricated).

**Run 1 (the first attempt, also published)** ([`eval/agent-runs/results-run1.md`](../eval/agent-runs/results-run1.md); transcripts in `eval/agent-runs/run1-*/`)

| KPI | A. Spreadsheet agent | B. Graph, no claim check | C. Graph + claim checker |
|---|---|---|---|
| Answer accuracy | 9/20 (45%) | 17/20 (85%) | 16/20 (80%) |
| Claims with a valid citation | n/a | 65/74 (88%) | 87/87 (100%) |
| Wrong claims shown | 11 wrong answers | 5 wrong claims; 3 wrong answers | 0 wrong claims; 4 wrong answers |
| Trap hits | 6/14 | 1/14 | 1/14 |

What run 1 showed: the graph agents declined to answer three questions (GQ-06, GQ-18, GQ-19) because the tools then available could not show which "Compliant" tracker rows the graph contradicts, or which already-expired evidence an audit requests. We added the `stale` and `evidence` commands (and MCP tools), tightened the agent prompts, and re-ran everything as run 2. Both runs are kept, and run 2 is not a re-roll of the same tools.

What to read from it, and what not:

* The spreadsheet agent was deliberately given everything a normal tracker holds **except** the NIST crosswalk, the decision log, pending proposals and path ids ([protocol](../eval/agent_compare/README.md)). Its 45% shows what that missing connected context costs, not that models cannot read spreadsheets. Often it said honestly that the files could not answer; the scorer counts those as wrong.
* In run 2 the claim checker does **not** raise accuracy over the unchecked graph agent (both 95%). What it changes is what the user is shown: wrong claims 3 -> 0 and valid citations 96% -> 100%.
* One answer is still wrong in both graph setups (GQ-11, the decoy case: `valid_replacements` does not match). The checker does not catch a wrong answer whose claims are individually valid.
* One model, one question set, one fictional company.

## Mapping quality

40 hand-labelled adopted controls, 800-53 targets, top 10, leave-one-out. A hit is a primary or acceptable id in [`eval/control_labels.yaml`](../eval/control_labels.yaml); recall counts primary ids only. Full table: [`eval/mapping_scores.md`](../eval/mapping_scores.md).

| Method | Precision@5 | Recall@10 | MRR | Controls with a hit in top 10 |
|---|---|---|---|---|
| Full-text only | 0.165 | 0.433 | 0.418 | 31/40 |
| Vector only | 0.175 | 0.479 | 0.495 | 32/40 |
| Hybrid (WRRF 0.7/0.3, c=60) | 0.195 | 0.542 | 0.554 | 29/40 |
| Hybrid + graph re-rank | 0.195 | 0.562 | 0.573 | 31/40 |

Hybrid beats each single method on MRR (0.554 vs 0.495), and the graph re-rank improves on hybrid (0.573). In leave-one-out only the family signal can fire, so the re-rank gain is small. **Precision@5 of about 0.2 is modest**: the suggestions are a shortlist for a human, not mappings. The mapper-agent row is not measured.

## Limits in full

* **Not audit or legal advice.** Crosswalk does not certify compliance. Coverage means "an approved mapping and unexpired evidence exist in this graph", nothing more.
* **Fictional company.** Harbor & Pine, its people, systems, evidence and decisions are invented.
* **Suggestions are proposals.** Agents write `:Proposal` nodes only. A human approves or rejects each one; a proposal that fails verification needs an explicit `--force`, which is recorded.
* **Agents never send anything.** Evidence requests are stored drafts; a human sends them.
* **NIST says its crosswalks give "a general indication", not proof of equivalence.** Treat inherited coverage as a head start for review. Inheritance is one crosswalk hop only, by decision (two hops was too loose).
* **Mapping precision is modest** (Precision@5 about 0.2).
* **Ground-truth labels are AI-assisted.** The 40 control labels were written with Claude Sonnet from control text and NIST statements only, without seeing the company's existing mappings, then reviewed by the architect. They are not an auditor's judgement.
* **One model, one question set.** The expected answers come from our own oracle. Do not extrapolate.
* **The claim checker verifies paths, not truth outside the graph.** A wrong answer built from individually valid claims gets through (GQ-11 in run 2).
* **Search limits (Relate 1.2.0).** Vector search is exact (brute force), which is fine at about 1,200 requirements. Full-text search has no stemming and no phrase matching by default, which is why hybrid beats full text alone.
* **One writer at a time** on an embedded directory store. `crosswalk-mcp` is the one process that writes for agents.
* **Platforms.** Developed on Windows 11 with Python 3.12 and Relate 1.2.0; Linux (Ubuntu, Python 3.12) is tested in CI on every push. macOS commands are given but untested by us. The Windows cold start (fresh copy of the repo and a new venv, first result in 99 s) was run on the development machine, not a clean one.
* **Privacy.** The core runs fully offline. The same MCP servers work with any MCP client, including one backed by a local model. Relate telemetry is opt-out (`DO_NOT_TRACK=1`); `crosswalk agent setup` sets it in the servers' environment.
